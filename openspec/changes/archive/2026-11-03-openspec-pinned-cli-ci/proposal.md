## Why
Nothing in this fork pins or checks OpenSpec. Agents ran whatever `openspec` was installed globally, so the artifacts they wrote drifted from what the CLI expects: 16 of 18 archived changes have no `.openspec.yaml`, and OpenSpec 1.16.0 (`openspec validate --all --strict`) reports seven main specs with requirements over 500 characters or a Purpose under 50. No skills tell an agent how to create a change, and `ci.yml` checks only `commit-kinds`, so the next defect lands the same way.

## What Changes
- `openspec/cli.pin` holds the one OpenSpec version this repo works with (`1.16.0`). It is installed globally on the machine (`npm i -g @fission-ai/openspec@$(cat openspec/cli.pin)`); CI runs that exact version through `npm exec`. AGENTS.md records how the version is raised: the global install, the pin and the regenerated skills in one commit.
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) are generated by the pinned CLI for Claude Code (`.claude/skills/openspec-*`) and Codex (`.agents/skills/openspec-*`) and committed. `.claude/` and `.agents/` become infrastructure paths.
- A new `openspec` job in `ci.yml` runs `openspec/check.sh` with the pinned CLI: `openspec validate --all --strict`; no main spec Purpose starting with `TBD - created by archiving change`; every active change has `.openspec.yaml`; every skill's `generatedBy` equals the pin; no archived change keeps an open task that is not `[human]`. The same script runs locally before a push.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply` / `operations.archive` guidance that point at AGENTS.md instead of restating it.
- The seven main specs the strict validation flags are rewritten without losing meaning (`android-app`, `bytecode-loading`, `fmt-opus`, `harfbuzz`, `sdl-events`, `sdl-touch`, `sys-full-path`). The archive is not repaired.

## Capabilities

### New Capabilities
- `openspec-checks`: the pinned OpenSpec version and the CI job that validates this repository's specs, changes and skills against it.

### Modified Capabilities
- `android-app`, `bytecode-loading`, `fmt-opus`, `harfbuzz`, `sdl-events`, `sys-full-path`: long requirements rewritten to one behaviour each, details moved into scenarios or split into further requirements (a split is REMOVED + ADDED, since a MODIFIED requirement may not drop a scenario). Same behaviour.
- `sdl-touch`: a Purpose that says what the capability is for, written into the main spec when the change is archived (a delta cannot carry a Purpose). Same behaviour.

## Non-goals
- Repairing archived changes (missing `.openspec.yaml`, old formats).
- Any change to code under `src/`, `libs/`, `include/`, `other/`.

## Impact
Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/workflows/ci.yml`, `.github/infra-paths`, `AGENTS.md`. Every later change is created with `openspec new change` and must pass the new CI job.
